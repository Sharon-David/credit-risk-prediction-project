§ 01 · Cloud Architecture Motivation

Overcoming Monolithic Infrastructure Bottlenecks in Production

Traditional financial lending systems rely on monolithic, always-on servers or manual data handoffs. These legacy architectures waste expensive compute during off-peak hours, become single points of failure under sudden load spikes, and fail modern regulatory compliance standards.

Cloud Problem · The Monolithic Dilemma

Compute Waste, Cold Latencies & Blast Radius

On-premise servers and dedicated EC2 instances bill 24/7 regardless of whether an applicant is actively applying for a loan. In retail lending where traffic is highly bursty, maintaining provisioned infrastructure incurs heavy baseline overhead while still risking timeouts during surge periods.

Furthermore, monolithic pipelines lack isolated fault boundaries: a failure in batch data cleaning can freeze real-time underwriting APIs, and permissions are often dangerously coupled under overly broad administrative credentials.

The Serverless Alternative Function-as-a-Service (FaaS) and SageMaker Serverless scale compute strictly proportional to incoming HTTP requests, scaling to absolute zero when idle.
Cloud Solution · CreditIQ Architecture

Decoupled Storage, Ephemeral Compute & Auditability

CreditIQ decouples persistent storage completely from ephemeral compute. Raw data and model weights reside in durable Amazon S3 buckets, queried serverlessly with Amazon Athena and preprocessed through managed AWS Glue jobs.

Online inference requests route through Amazon API Gateway and AWS Lambda directly to a containerized SageMaker Serverless endpoint. Crucially, every transaction is committed to Amazon DynamoDB with sub-millisecond writes to provide an immutable compliance trail.

Synchronous Pipeline Orchestration Managed with AWS Step Functions state machines to ensure deterministic transitions and automated failure alerting via CloudWatch.
